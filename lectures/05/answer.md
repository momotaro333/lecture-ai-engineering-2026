- 取り組んだレベル：発展
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：`app/retrieval.py`のGraph探索を改良した。従来の`next_page`と`mentions`に加えて`related_term`エッジもたどり、ページ・用語をノード、関係をエッジとして最大2 hopまで探索する。さらに、質問に含まれる用語（PEFT、LoRA、QLoRAなど）が本文・タイトルに現れるページを優先する再順位付けを加えた。関連ページを拾いつつ、質問と無関係な共通用語ページが上位になることを抑える設計である。
- 比較した質問と、固定した条件（モデル・対象資料など）：質問は「第2回のPEFT・LoRA・QLoRAの違いを、学習する対象とベースモデルのメモリ使用量の観点から説明してください。」。基本RAG（`uv run python -m app.agent --trace`）と改良Graph（`uv run python -m app.agent --graph --trace`）を、同じ`gemini-3.5-flash-lite`、第1〜3回の資料、同じ質問で実行した。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：基本RAGはPEFT・LoRA・QLoRAの関係と、LoRAは元の重みを固定して差分を学習し、QLoRAは4bit量子化を加えることを説明し、第2回・PDF p.51, 52を引用した。4.98秒、入力2,894／出力701トークン、モデル応答2回、$0.002621だった。改良Graphも同じp.51, 52を根拠に正しく回答した。traceの入口は`lec02-main-p051`、`p052`、`p060`で、展開候補には`lec02-main-p054`、`p058`、`p059`、`p061`などが含まれた（最大2 hop）。4.42秒、入力6,005／出力512トークン、モデル応答2回、$0.003082だった。
- 改善した例と、残る失敗・制約：改良GraphはPEFTの説明ページとLoRA・QLoRAの比較ページを関連用語から同時に候補へ残せたため、複数の関連用語を比較する質問に向いている。一方、`lec01-main-p058`や第3回のメモリ関連ページなど、質問の直接の根拠ではない候補も展開された。今回の基本RAGも正答できたため、正答率の改善は確認できず、改良後は入力トークン数と費用が増えた。グラフの関係が不足している用語や、資料にない質問には効果がない。
- 気づき・疑問：単一ページで答えられる質問では基本RAGの方が安く、改良Graphは章をまたぐ比較や複数用語の関係を調べる場合に採用したい。今後は候補ページをモデルにすべて渡すのではなく、用語一致数とベクトル距離を組み合わせて上位候補をさらに絞ると、根拠を保ったまま費用を下げられそうである。
