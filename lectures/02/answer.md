## 宿題

- 変えた設定やデータ：

用語集にない語: 7 問（RAG、埋め込み、プロンプトインジェクション、Transformer、知識蒸留、ベクトル DB の 6 語と、架空の「最終課題の締切」）
元の演習と同じく、形式と内容を分けて採点した。
形式: 学習データ（用語集の定義文）と同じ書式か。Markdown 記法なし・改行なし・「〜とは、」「〜は、」の前置きなし・212 字（学習データの最大長）以内・「。」で終わる、をすべて満たせば OK。学習データの定義文は 58/58 件が満たす。元の演習の JSON 検査の代わり。
内容: 「回答に含まれるべき語」のグループをすべて含めば正解。「記載がありません／わかりません」は回避、それ以外は誤答。
比較対象として「用語集を検索する仕組み」を 2 つ作った。
検索のみ: 文字 2〜3gram の TF-IDF で類似度を測り、閾値 0.15 未満なら「記載がありません」と返す。
検索＋基盤モデル（RAG）: 上位 2 件の定義をモデルに渡して答えさせる。
- 結果（比較表や数字）：
各セルは「形式 OK 率 / 内容の正解率 / 形式も内容も OK の率」。
方式	用語集にある語	言い換え	用語集にない語	1 問あたりの秒数
学習前	0% / 0% / 0%	0% / 10% / 0%	0% / 29% / 0%	7.7
学習後（LoRA）	100% / 70% / 70%	80% / 50% / 40%	86% / 0% / 0%（誤答 100%）	3.2
検索のみ	100% / 80% / 80%	100% / 90% / 90%	100% / 0% / 0%（「記載なし」57%、誤ヒット 43%）	≒0
検索＋基盤モデル（RAG）	30% / 80% / 20%	60% / 80% / 50%	57% / 29% / 14%（「記載なし」43%）	1.4
形式は、学習前は全区分で 0%。どの回答も太字や箇条書きを使った長い解説で、160 トークンの上限で途中で切れていた。学習後は 80〜100% に上がり、崩れたのは学習データに無い短い答え（「12月24日（木）18:00〜19:00（JST）」のように「。」で終わらない例など）だけだった。RAG は内容が高いのに形式は 30〜60% で、「LoRA は、…」の前置きや単語だけの回答が多かった。
学習前は講座固有の意味を知らず、一般的な意味で答えた（temperature＝温度、ハーネス＝スポーツ用具、Pi＝円周率）。
学習後は、学習と同じ聞き方なら定義文をかなり再現したが、一部を作り変えた例もあった（QLoRA を「4ビットや2ビットで圧縮したRAMに接続」、ハーネスを「ケーブルのようなもの」）。言い換えでは、逆引き（ハルシネーション）や具体的な事実（HTTP 429）を落とした。
学習後は、用語集にない語でも書式を保ったまま全問を用語集の文体で言い切った。最終課題の締切は「12月24日（木）18:00」と作り話になり、学習前は大まかに答えられた RAG やベクトル DB も誤答になった。
検索は、当たれば原文を返すので正確だった。失敗は次のとおり。
「LoRA」で引くと QLoRA が最上位に来る。
「Pi」は短すぎて類似度が閾値に届かない。
用語集にない語が字面の近い別項目に誤ってヒットする（プロンプトインジェクション→プロンプト、締切→既定モデル）。
RAG は、検索の誤ヒットをモデルが「記載なし」と判断して救った場合がある一方、近いが違う定義を渡されると混同した。
同じ設定で 3 回学習すると、学習後の内容の正解率は「用語集にある語」60〜80%、「言い換え」40〜50% の間で揺れた。GPU 上の学習は完全には再現しない。
判定は機械的なルールで、問題数は区分ごとに 7〜10 問、生成も 1 回だけなので誤差は大きい。例えば学習前の RAG の回答は略語の展開を誤っていたのに、内容が正解扱いになった。
- ファインチューニングが向く場面・向かない場面についての考察：
向く場面:
回答の形式・口調・文体を揃えたいとき。第 2 回の FAQ では JSON の形式遵守率が 10% → 100%、今回も用語集の書式の遵守率が 0% → 80〜100% に上がった。どちらも数分の学習で効いた。プロンプトで指示するだけでは、小さいモデルは書式を守れない（RAG の形式は 30〜60%）。
決まった聞き方で、決まった定型の答えを返せばよい場面。
推論のたびに検索や長い文脈を渡したくない場面（入力が短く済む）。
用語や言い回しが一般の意味と違うドメインに、モデルの振る舞いを寄せたい場面。内容の正解率は 0% → 60〜80%。
向かない場面:
事実を正確に答える必要がある場面。形式はほぼ完璧になったが、内容は言い換えると 50% 前後に落ち、定義の作り変えや似た語の混同も起きた。覚えたのは「質問文 → 定義文らしい文」の対応で、使い回せる知識にはなっていない。
知らないことに「わからない」と答えるべき場面。用語集外の質問への誤答が 100% で、学習前に持っていた一般知識も劣化した。書式が整っているぶん、誤りに気づきにくい。
情報が頻繁に更新される場面。検索なら用語集を書き換えるだけですぐ反映されるが、学習は毎回、再学習と再評価が要る。
根拠（出典）を示す必要がある場面。
まとめ: 元の FAQ 演習と同じく、ファインチューニングは「形式」には強く効くが、「内容」、特に知らないことへの判断は保証しない。用語集のような知識の参照は検索や RAG を主にし、ファインチューニングは回答の書式や口調を揃える役に回すのがよい（例: RAG の回答を用語集の書式で返すように学習させる）。ファインチューニングでやるなら、次の 3 つが改善策になる。
学習データに言い換え・逆引きの例を加える。
用語集にない質問に「記載なし」と答える例を加える。
「検索結果を根拠に答える」形式そのものを学習させ、RAG と併用する。
