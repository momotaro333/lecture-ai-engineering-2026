## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 質問「AIE2026の講座で使う「lecNN-start タグ」とは何ですか？」
  - `app.ask`（素のLLM）：「講義資料の中でコードブロックの開始位置を示す目印（`<!-- lec01-start -->` のようなコメント）」と、もっともらしいが**誤った内容**を自信をもって長々と答えた（出力 407 トークン）
  - `app.agent`：`search_glossary` で用語集を引き、「各回の演習開始時点のコードに付けた Git タグ（例：`lec03-start`）。前の回が終わっていなくても、そこからブランチを作れば演習を始められる」と**正しく**、簡潔に答えた。末尾に「関連する回：第1回」も付いた
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「LoRAとQLoRAの違いは？」→ `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。用語を1つずつに分けて検索していた
  - 「lecNN-start タグ」→ `search_glossary({'query': 'lecNN-start タグ'})` の1回
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 「LoRAとQLoRAの違いは？」で `requests=2`（tool_calls=2）。1回目でツール2つをまとめて呼び、2回目で結果を読んで回答した
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int)`：指定した回の用語から1つを選び、「この用語の意味は？」という問題と答えを JSON で返す
  - docstring：「指定した回（1始まりの整数）の用語から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。答えはすぐに見せず、利用者が考えてから示すこと。」
  - 「第2回の内容から確認問題を1問出して」→ `make_quiz({'lecture': 2})` が呼ばれ、docstring のとおり答えは伏せたまま問題だけを出した

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - `INSTRUCTIONS`（app/agent.py）と `search_glossary` の docstring（app/tools.py）を書き換え、次の4条件で同じ2つの質問を `--trace` 付きで実行した（モデル：gemini-3.5-flash-lite、各1回）
    - A：元のまま
    - B：`INSTRUCTIONS` を「質問には自分の知識で簡潔に答える。ツールは本当に必要なときだけ使う。」の1行に変更
    - C：`INSTRUCTIONS` は元のまま、`search_glossary` の docstring を `"""用語データ。"""` だけに変更
    - D：B と C の両方
  - 質問：①「LoRAとQLoRAの違いは？」 ②「第2回の内容から確認問題を1問出して」
  - 比較のあと、コードは元に戻した
- 結果：

  | 条件 | ① tool call | ① requests | ② tool call | ② requests | 回答の変化 |
  |---|---|---|---|---|---|
  | A 元のまま | `search_glossary(LoRA)`, `search_glossary(QLoRA)` | 2 | `make_quiz(2)` | 2 | 用語集の定義どおりに答え、末尾に「（第2回）」 |
  | B INSTRUCTIONS 変更 | A と同じ | 2 | A と同じ | 2 | 内容はほぼ同じ。末尾の「第N回」が消えた |
  | C docstring 変更 | A と同じ | 2 | A と同じ | 2 | A とほぼ同じ（「関連する回：第2回」あり） |
  | D 両方変更 | **呼ばれない** | **1** | `make_quiz(2)` | 2 | ①は自分の知識だけで長めに回答。「70Bモデルを1枚のGPUで」など用語集にない内容が加わった。「第N回」はなし |

  - 入力トークン（①）：A 1388 → B 1230 → C 1254 → D 268。D はツールの戻り値を読まない分、大きく減った
- 気づき・疑問：
  - ツールを使わせる指示は、`INSTRUCTIONS` と docstring の**どちらか一方**に残っていれば守られた。B では docstring の「答える前に使うこと」が、C では `INSTRUCTIONS` の「必ず search_glossary で確認する」が効いていたと考えられる。両方を消して初めてツールが呼ばれなくなった
  - `make_quiz` は D でも呼ばれた。「確認問題」という依頼と、docstring の「確認問題を求められたときに使う」が直接対応しており、モデルが自分で問題を作るより、ツールを使うほうが自然だったのだと思う
  - 「第N回を示す」のような出力の形は `INSTRUCTIONS` にしか書いていないため、B・D では消えた。ツールを使うかどうかは docstring、回答の形は `INSTRUCTIONS` と役割を分けると整理しやすい
  - D は速く安い（requests 1回）が、講座の定義に基づかない内容が混ざる。根拠を用語集に揃えたいなら、ツール利用の指示は省けない
  - 疑問：各条件1回ずつしか試していない。出力は毎回変わるので、何回か繰り返したときにどの程度安定するのかは未確認
